# Original brief coverage

This maps the original Desktop Rug brief to the implementation and its evidence. It does **not** declare the complete initial-release definition of done satisfied. The current result is a runnable Windows preview with automated and native-fixture verification; physical desktop acceptance remains open.

## Reading the evidence

- **Implemented** means the behavior exists in source. It does not imply a person has exercised it on every supported Windows configuration.
- **Core verified** means framework-independent automated tests passed, covering physics, contact, transforms, settings, Peek, frame cadence, display coordinates and material/language compatibility. The current count is recorded in [VALIDATION.md](VALIDATION.md).
- **Native fixture verified** means the actual Windows APIs or application window procedure were exercised with isolated named objects or application-owned windows outside the visible desktop. Synthetic backgrounds, input messages, and display definitions are explicitly fixtures.
- **Real shell observed** means read-only discovery succeeded against Explorer on the test machine: Windows 10 build 19045, one physical display at 100% scaling. This does not establish Explorer restart, hardware input, or multi-monitor behavior.
- **Physical acceptance pending** means the scenario has not been performed against the user's visible desktop, Windows 11, multiple physical monitors, or an actual session/display transition.

Current executed results, environment, and performance scope are recorded in [VALIDATION.md](VALIDATION.md). [MANUAL_TESTS.md](MANUAL_TESTS.md) is the remaining physical acceptance checklist. A pending item must not be represented as a pass because a related fixture or unit test passes.

## Optional enhancements and explicit limits

The 0.2 portable off-screen WPF pipeline measured 59.85 FPS including physics, rendering and native input-region updates. This is stronger evidence than the isolated CPU renderer benchmark, but still does not certify visible presentation on other machines or multiple physical monitors. [FramePipelineDiagnostics](../src/DesktopRug.App/Services/FramePipelineDiagnostics.cs) reproduces that scope, and [RugHitRegion](../src/DesktopRug.App/Windows/RugHitRegion.cs) supplies the optimized, hole-preserving native hit region.

Touch and pen support are optional in the original brief. [PointerInput](../src/DesktopRug.App/Interop/PointerInput.cs) and the input window now include pointer decoding, pressure handling, cancellation, and single-active-pointer behavior. Native structure/layout and decoded touch/pen fixture cases pass; no touch or pen hardware was used. These checks do not imply hardware certification.

The cloth self-contact solver substantially reduces tunneling and keeps folds separated in covered scenarios, but it uses a finite work budget and does not provide exact continuous edge–edge collision for every possible knot. The roll is a guided animation. Icon tracking follows shell-reported bounds and cannot invent intermediate positions unavailable from Explorer. The measured renderer target is not an end-to-end frame-rate guarantee.

## Reproducing the available checks

Use the restore/build/test/publish commands in [README](../README.md) and the exact validation commands in [VALIDATION.md](VALIDATION.md). Run the resulting executable with `--diagnostics` and a local output directory to reproduce read-only shell discovery, application-owned offscreen fixtures, unique named-object checks, rendered comparisons, and timing reports. Generated evidence belongs in ignored local artifacts, not in public source control.

The diagnostic output deliberately retains `manualInteractionVerified: false` and physical-monitor/touch verification flags where appropriate. It records whether offscreen hit routing is available, rather than silently treating an unavailable platform check as a pass. None of these commands should move the user's pointer, restart Explorer, alter monitor settings, enable sign-in launch, or activate a foreground window.

The remaining release gate is the visible, physical Windows acceptance checklist: real mouse interaction and icon activation, Windows 11, multiple physical displays and DPI changes, Explorer restart, fullscreen/virtual-desktop transitions, lock/resume, and opt-in sign-in behavior. The original definition of done remains open until that evidence is obtained and recorded.
